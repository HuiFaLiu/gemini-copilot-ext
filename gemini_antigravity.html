开源项目横向拆解：导航学 Voyager，限额取三家所长

截至 2026 年底，围绕 gemini.google.com 的开源插件已形成清晰的分工：以 Voyager 为代表的综合增强套件在对话导航与 DOM 抗改版架构上最成熟，而 Gemini Usage Bar、Usage Meter 与 Unofficial Gemini Usage Tracker 则完整验证了网页端限额读取的三条可行路径与风控边界。

对话内导航：语义适配层与右侧时间轴锚点设计

网页端 Gemini 基于 Angular 与 Material 组件构建，类名混淆且迭代频繁。如果将 DOM 选择器硬编码在业务逻辑里，一次前端发版就可能导致导航栏整体失效。

参考 Voyager 的三层解耦思路，导航模块应当将“页面长什么样”与“时间轴怎么交互”彻底分离。独立维护 src/sites/gemini.ts 语义适配层，通过特征属性与语义标签（如对话容器、用户提问节点、模型回复节点、发送/停止按钮、侧边栏容器）提供多级回退选择器，上层导航逻辑只消费抽象的 TurnNode[] 列表。

核心交互与定位精度

  • 右侧悬浮时间轴轨道：默认收起为极细圆点轨道，不遮挡正文；当前视口所在轮次通过 IntersectionObserver 高亮联动。
  • 悬浮预览与直达跳转：鼠标悬停节点显示该轮用户 Prompt 前 60 字摘要与轮次序号；点击后调用 scrollIntoView({ behavior: 'smooth', block: 'start' }) 并施加 1.2 秒边框高亮闪动。
  • 长对话筛选与星标：展开面板后支持按关键词即时过滤轮次、仅看含代码块/公式的回复，以及本地星标固定关键轮次。

SPA 生命周期与样式隔离

  • 增量索引与防抖：利用 MutationObserver 监听对话流容器子节点增删，对流式输出期间的高频 DOM 变动做 200ms 防抖，避免重排卡顿。
  • 路由切换自愈：同时监听 popstate、history.pushState 补丁及 URL 对话 ID 变化，切换会话时自动清空旧索引并重建当前对话节点。
  • Shadow DOM 沙箱：所有注入 UI 挂载于 attachShadow({ mode: 'open' })，彻底隔绝 Gemini 全局 CSS 污染，并自动同步页面浅色/深色主题变量。

用量限额监控：高频自动刷新的技术路径与风控边界

Google 目前未对网页端 Gemini 开放官方限额查询 API，当前用户的周期限额与重置时间仅呈现在登录态下的 gemini.google.com/usage 页面及底层内部接口中（参见 Unofficial Gemini Usage Tracker 与 Usage Meter 的实测说明）。因此，“每隔若干秒自动刷新”在工程上必须先解决数据来源与防风控/低开销两大矛盾。

关键工程警示：切勿以 5–10 秒的固定间隔反复创建隐藏 iframe 加载 gemini.google.com/usage。这不仅会持续消耗大量内存与 CPU，还因依赖 declarativeNetRequest 剥离安全响应头而显著放大触发 429 限流或账号异常检测的风险。

双层数据获取管线（轻量优先，渲染兜底）

  • 首选通道（轻量直连）：复用当前浏览器已登录的同源 Cookie，在页面上下文或后台优先尝试轻量接口（如参照 Usage Meter 探测公开前端包中的 GraphQL/Relay 描述符直连 JSON，或同源 fetch('/usage') 解析初始载荷）。单次开销极低、无 DOM 渲染负担。
  • 降级通道（受控隐藏 iframe）：当直连结构变更或页面强依赖客户端渲染时，自动回退至 Gemini Usage Bar 验证过的方案——通过 declarativeNetRequest 仅对 gemini.google.com/usage 放行同源嵌入，解析出百分比与重置时间后立即销毁 iframe，且自动拉长降级轮询间隔（≥120 秒）。

展示位置、状态预警与用户可控性

  • 主展示位（顶栏自适应胶囊）：固定于 Gemini 顶部栏右侧空白处，实时显示已用/剩余百分比与微型进度条；点击展开明细浮层，列出当前周期限额、周限额、精确重置倒计时与手动刷新按钮，并支持 Alt+U 快捷显隐。
  • 三级色彩预警：参考 Usage Meter 的直观阈值，<70% 显示翠绿，70%–89% 转为琥珀黄，≥90% 亮红提醒；可选同步到浏览器工具栏扩展图标 Badge。
  • 异常 fail-closed：未登录、切换 Google 多账号或解析失败时，保留上一次有效读数并标记“需刷新/未登录”，绝不伪造 0% 误导判断。

值得同步纳入的高价值扩展功能

综合社区高频诉求（包括 Voyager 与 AI Toolbox for Gemini 的用户反馈），插件最容易落入“功能堆砌导致卡顿与维护失控”的陷阱。建议按使用频率与维护成本划分为三层，首版聚焦 P0 与低维护成本的 P1 效率项。

系统架构与推荐技术栈（Manifest V3）

为了让插件体积轻盈、热重载流畅且方便 Antigravity 自动生成与维护，推荐采用 Vite + TypeScript + Preact（或纯原生 TS）+ Shadow DOM + Chrome Manifest V3，测试层配置 Vitest + Playwright。相比直接堆砌重型前端框架，Preact + Scoped CSS 打包体积仅数十 KB，注入 gemini.google.com 几乎零感知开销。

基于 Google Antigravity 的四阶段落地工作流

Google Antigravity 具备项目级 Rules / Agent Skills（默认目录 .agents/skills，参见 Antigravity Agent Skills 文档）以及内置 /browser 浏览器子代理（在 Antigravity App v2.30+ 中可直接使用内置浏览器，或在 IDE/CLI 中通过 Chrome DevTools MCP 连接本地 Chrome v144+，参见 Antigravity /browser 文档）。开发浏览器插件时，最大的效率杠杆在于让 Antigravity 先用浏览器看真实 DOM，再写适配代码，最后自己截图验收。

阶段 核心目标 Antigravity 推荐指令与工具用法 完成验收标准

请严格按以下顺序分阶段推进，在写业务代码前先输出实现计划（Implementation Plan）：

1. 先在项目根目录创建 AGENTS.md，固化以下铁律：
   - 所有依赖 gemini.google.com 页面结构的选择器必须集中放在 src/sites/gemini.ts；
   - 所有注入页面的 UI 必须挂载在 Shadow DOM 内，自动适配 Gemini 浅色/深色主题；
   - 最小权限原则：host_permissions 仅限 https://gemini.google.com/*，禁止连接任何第三方服务器；
   - 限额刷新必须采用“回复结束事件触发 + 活跃标签页可配轮询（默认 45s，下限 15s）+ 隐藏自动暂停 + Service Worker 单飞去重 + 429 指数退避”。
2. 使用 /browser 打开 https://gemini.google.com 和 https://gemini.google.com/usage（如遇登录请暂停交由我接管），实地探测当前对话轮次 DOM 结构、发送/停止按钮状态以及限额数据来源，先整理探测报告再开始编码。
